## 1. Цель AI в системе

AI усиливает продукт за счёт:
- автогенерации черновика карточки товара (title/description/tags/attributes)
- помощи модерации/публикации
- последующей персонализации и рекомендаций

---

## 2. Текущее состояние (на 2026-01-27)

### 2.1 Контур gateway (актуально)
- RU сервисы **не обращаются к OpenAI напрямую**
- Весь внешний AI-трафик идёт через **EU шлюз** `ai.voicecrm.online`
- Аутентификация: `X-AI-Internal-Token`

### 2.2 Provider switch
- `AI_PROVIDER=gateway` — основной режим
- `AI_PROVIDER=openai` — только для локальных/dev сценариев (если требуется)

---

## 3. Ближайшие шаги (2–4 недели)

1) **Качество промпта / валидный JSON**
   - строгая схема JSON (Pydantic schema enforcement)
   - автоматический retry при invalid-json
   - метрики: доля валидных ответов

2) **Категоризация и атрибуты**
   - словарь атрибутов по категориям
   - нормализация (цвет/материал/размер)
   - маппинг в доменную модель

3) **Кэширование / дедупликация**
   - checksum media → reuse результата
   - идемпотентность ai_jobs

---

## 4. Среднесрок (1–2 квартала)

- мультимодальный поиск (text+image) через Meili/векторизацию
- “assistant for seller” (подсказки, улучшение описания)
- safety/PII правила

---

## 5. Инфраструктурные принципы (AI)

- ключи OpenAI храним только на EU шлюзе
- в RU контуре только `AI_INTERNAL_TOKEN`
- observability: отдельные логи gateway + request-id (по возможности)
