---

## 1. Назначение документа

Данный документ фиксирует **дорожную карту развития AI-возможностей платформы Clothing**.

Цель AI в системе:
- усиливать продукт,
- автоматизировать рутину,
- повышать качество данных,
- **не разрушая доменную модель и бизнес-логику**.

AI рассматривается как **асинхронный сайд-эффект**, а не источник истины.

---

## 2. Базовые принципы AI в платформе

1. **AI ≠ бизнес-логика**
2. **AI не меняет состояние напрямую**
3. **AI работает через jobs + worker**
4. **AI результат — данные, не решения**
5. **Финальное решение — за state_machine**

---

## 3. Архитектурное место AI

API
↓
AIJob (DB)
↓
Queue (Redis)
↓
Worker
↓
AI processing
↓
DB update / Domain Event

AI всегда:
- асинхронен
- воспроизводим
- масштабируем горизонтально

---

## 4. Текущий baseline (2026 Q1)

### Реализовано
- AIJob модель
- Redis queue
- Worker-процесс
- Интеграция с доменом через события
- Безопасная изоляция от core-бизнеса

---

## 5. Roadmap по этапам

### 🔹 Этап 1 — Foundation (готово)

**Цель:** стабильная инфраструктура

- [x] Единая архитектура API + worker
- [x] Абсолютные импорты
- [x] Очередь задач
- [x] Изоляция AI от домена

---

### 🔹 Этап 2 — Product AI (Q1–Q2 2026)

**Фичи:**
- AI-анализ фото товара
- AI-оценка качества изображения
- AI-теги (цвет, тип, материал)
- AI-рекомендации категории

**Технически:**
- новые `AIJob.type`
- отдельные handlers в `jobs.py`
- расширение `models.py`

---

### 🔹 Этап 3 — AI Assistants (Q2–Q3 2026)

**Фичи:**
- AI-помощник модератора
- AI-предложение улучшений карточки
- AI-анализ ошибок контента

**Особенности:**
- AI не применяет изменения сам
- только рекомендации + confidence score

---

### 🔹 Этап 4 — AI Automation (Q3–Q4 2026)

**Фичи:**
- автопредложение статусов
- AI-триггеры (через outbox)
- batch-обработка

**Ограничения:**
- state_machine остаётся gatekeeper
- возможен feature-flag режим

## 6. Где расширять систему

| Задача | Файл |
|------|------|
| Новая AI задача | `apps/api/models.py` |
| Очередь | `apps/api/queueing.py` |
| Worker logic | `apps/api/jobs.py` |
| API запуск | `apps/api/main.py` |
| Domain события | `apps/api/events/*` |

---

## 7. Метрики и контроль качества

Для каждой AI-фичи должны быть определены:
- precision / recall (если применимо)
- latency
- % отказов
- влияние на бизнес-метрики

---

## 8. Риски и ограничения

- AI не должен:
  - блокировать core-флоу
  - быть SPOF
  - иметь side-effects без логирования

- Любая AI-автоматизация:
  - только после периода recommendation-only
